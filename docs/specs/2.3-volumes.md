# Spécification — 2.3 Découpe en volumes, recollement à l'ouverture

## Contexte

Les partages de fichiers restent limités en taille (clé USB FAT32, dépôts en
ligne) : la découpe en volumes reste un besoin réel. La roadmap réintroduit
donc la version moderne du multivolume, en évitant l'héritage disquette/CD.

## Objectif

Découper une archive existante (tout format) en parties numérotées
`nom.001`, `nom.002`… et réassembler automatiquement les parties à
l'ouverture pour toutes les opérations (listing, extraction, test).

## Critères d'acceptation

1. Commande `split_archive(src, dest_base, part_size)` : parties
   `dest_base.001`, `.002`… de `part_size` octets (dernière partie plus
   courte) ; parts existantes → erreur ; progression + annulation +
   nettoyage des parties déjà écrites en cas d'échec ; durée renvoyée.
2. Ouverture d'une partie `xxx.001` : les parties consécutives `xxx.002`…
   sont réassemblées en fichier temporaire (nettoyé après l'opération),
   puis le format est détecté sur le nom de base ; lister, extraire et
   tester fonctionnent comme sur une archive simple.
3. Une partie `.002`… ouverte directement fonctionne (recherche de
   `.001` et des suivantes).
4. UI : bouton « Découper… » dans la barre d'outils de l'archive, tailles
   proposées (10 Mo, 100 Mo, 1 Go), destination choisie via le dialogue
   d'enregistrement ; les fichiers `.001` sont ouvrables (dialogue et
   glisser-déposer).
5. Tests cargo : découpe + round-trip d'archive reconstituée ; refus
   d'écraser des parties existantes ; annulation sans parties résiduelles.

## Hors périmètre

- Multivolume natif ZIP/7z à la création (non supporté par les crates).
- Chiffrement des volumes (l'archive chiffrée reste chiffrée).
