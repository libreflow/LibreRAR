# Spécification — 3.1/3.2 Lecture et création TAR (gz, xz, zst)

## Contexte

Le TAR est le format du monde du développement : dépôts, sources, releases
GitHub, packages npm/tarballs. Zstandard est le standard de fait 2026
(rapide, moderne).

## Critères d'acceptation

1. Lecture, listing, extraction sélective et test d'intégrité des flux
   `tar`, `tar.gz`/`tgz`, `tar.xz`/`txz`, `tar.zst`/`tzst`.
2. Extraction protégée par `safe_join` : refus de `..` et chemins
   absolus (test dédié avec un TAR forgé contenant `../evil.txt`) ;
   nettoyage des fichiers déjà écrits si l'opération échoue.
3. Les noms d'entrées sont normalisés (préfixes `./` et slash initial
   retirés, entrées racine ignorées).
4. Création `create_tar` : variante `targz` (gzip) ou `tarzst`
   (Zstandard) ; parcours récursif identique aux autres formats ;
   progression, annulation, nettoyage d'archive partielle.
5. Dépendances auditées : `tar` **≥ 0.4.45** (CVE-2026-33056 corrigée à
   partir de 0.4.45), `flate2` (déjà transitive via zip), `xz2` (lecture
   xz), `zstd` (binders officiels).
6. Les volumes découpés (.001) s'appliquent aussi aux flux TAR.

## Hors périmètre

- Création tar.xz (compression lente, faible gain vs zst pour les usages visés).
- Tar multi-volume natif.
