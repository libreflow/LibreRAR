# Spécification — 1.2 Création d'archives 7z

## Contexte

LibreRAR lit et extrait les archives 7z (`sevenz-rust`, AES-256 supporté) mais
ne sait pas en créer. La création est limitée au ZIP/Deflate : la compression
LZMA2 du format 7z, nettement supérieure, est le deuxième écart majeur face
à WinRAR/7-Zip.

## Objectif

Créer des archives 7z (compression LZMA2), en clair ou chiffrées AES-256
avec l'en-tête également chiffré (noms de fichiers protégés).

## Critères d'acceptation

1. L'UI offre le choix du format (ZIP ou 7z) dans le panneau de création ;
   le dialogue d'enregistrement propose l'extension correspondante.
2. Backend : commande IPC `create_sevenz(id, dest, sources, password)`,
   déclarée dans `generate_handler!` ; les sources peuvent être des fichiers
   et des dossiers, parcourus récursivement ; les noms d'entrées gardent la
   convention des ZIP créés (préfixe par le nom de la source).
3. Mot de passe optionnel : contenu AES-256 (LZMA2 derrière), en-tête
   chiffré ; un mot de passe vide ou blanc = pas de mot de passe.
4. Progression et annulation identiques à la création ZIP (événement
   `operation-progress`, suppression de l'archive partielle en cas
   d'échec ou d'annulation, durée dans le résultat).
5. Round-trip testé (cargo) : création claire → listing/extraction sans
   mot de passe ; création chiffrée → listing sans mot de passe échoue
   (`PasswordRequired`, en-tête chiffré), mauvais mot de passe échoue,
   bon mot de passe → contenu identique.
6. `npm run lint`, `npm test`, `npm run build` et `cargo test` passent.

## Hors périmètre

- Compression parallèle du 7z (`sevenz-rust` compresse en flux séquentiel).
- Choix du niveau de compression LZMA2 (UI) — niveau par défaut.
- Volumes découpés (Phase 2.3).
